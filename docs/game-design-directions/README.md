## 数据集的三大独特杠杆（每个选题都应挂靠）

1. **每位玩家的上赛季 tier（8 档 Bronze→Challenger）嵌在普通单排里**——这是稀缺特征。
   多数公开 LoL 数据要么是职业赛（无低分段）、要么没有玩家段位标签。**任何"分技能
   水平"的设计论断都靠它。**
2. **冻结的历史补丁窗口（5.21–6.1，2016 预季赛）**——预季赛本身就是一次重大设计干预
   （符文/基石重做、ADC 装备重做、打野/视野改动）。已知设计冲击的保存快照 = 天然
   准实验底座，且不可再采集。
3. **22 万场业余单排 + 完整时间线 + 1310 万击杀事件**——即"天梯所体验的设计"，而非
   近年平衡论文几乎清一色研究的职业 meta。

**文献战略缺口**：近年竞技平衡/遥测工作压倒性地用职业/电竞数据，且框成预测、推荐或
聚合平衡。**分段位、业余天梯、面向设计的论断相对空白。**

## ⭐ 最高杠杆的单一投注：#2 + #4 合并成一篇

**"哪些英雄奖励精通？玩家 ban 的是'感觉不公平'的还是'真的强'的？"**

- 两者都骑在 tier 标签上，都面向设计，都学术开放；
- 合起来讲一个完整故事：**业余玩家如何"感知" vs "体验"英雄设计**——这正是电竞主导的
  文献结构上讲不了的；
- 核心论点可证伪：技能表达 = 每英雄"性能~段位"斜率；反不公平信号 = ban 率与实际
  power 的差（**被 ban 但胜率平庸的英雄 = 揭示的挫败感，anti-fun ≠ overpowered**）。

## 各方向的先行工作与缺口（详）

### #2 技能表达 / 精通回报（推荐主线）
- **直接问题只有业界/博客**：itero.gg "Mastery: 100 万+ 局统计"（每英雄精通→胜率曲线）、
  社区 skill-cap tier list——非同行评审，且用的是英雄熟练度点数而非玩家段位。
- **相邻学术**：PandaSkill（arXiv 2501.10049, IEEE ToG 2025，评职业玩家非每英雄）；
  Play Style Flexibility（arXiv 2402.05865）与 Proficiency-Congruency（arXiv 1512.08321）
  研究"玩家"的分段位通用性，非"英雄"作为被测天花板的单位。
- **缺口**：无同行评审论文从分段位业余人群产出**每英雄技能表达指标**并读作设计杠杆。
- **主要威胁**：选择混杂——不同段位选这个英雄的玩家群不同；需匹配比较 / 混合效应模型。
- **强论文动作**：把每英雄精通回报排名与 Riot 官方"预期难度"标签相关。

### #4 ban 作为设计偏好信号（推荐与 #2 合并）
- **业界框架有影响力但非学术**：Riot /dev "Champion Balance Framework"（2019）显式建模
  感知 vs 实际 power（"Sleeper Zone"象限）——是**引用资产而非抢先**。
- **学术 ban 工作多为预测/BP**（DraftRec 等）；最接近的 arXiv 2207.02736（补丁后 ban 行为）
  是补丁反应，非"感知失衡"分解。
- **缺口**：无同行评审把 ban 建模为**分段位的、相对实测 power 分解的感知失衡/anti-fun 信号**。
- **注意**：该时代 ban 有位置结构；用条件 logit / 离散选择建模而非原始 ban 率。

### #1 设计空间冗余与空档
- 聚类本身拥挤（大量博客/论文）；最强重叠 arXiv 2605.18338（2026，但目标是推荐）、
  arXiv 2502.01250（Valorant 平衡聚类，方法学模板）。
- **冗余/空档量化 OPEN**：定向搜"design gaps / under-served niche / roster coverage"只返回
  定性设计博客。**无人把"名单冗余 vs 空设计区"量化为健康度指标。**
- **强动作**：检测到的"空档"是否对应 Riot 2017–2020 后续英雄填补的位置——冻结补丁
  让这个外部检验很干净。

### #5 counterplay / agency（伴随指标）
- DiGRA 2024（art. 2218，LoL agency/predictability）直接理论化但**定性、无遥测量化**——
  这正是开口。构念效度是主要风险，宜与 #2/#4 配对。

### #3 翻盘/滚雪球（除非设计演化对比，否则不建议）
- 最拥挤：IEEE TVCG 2017（VIS 2016 snowball/comeback VA）+ IEEE DataPort Comeback 数据集
  （但基于**现代赏金机制**）。我们的补丁**早于目标赏金**——唯一活路是"Riot 工程化翻盘
  机制之前的翻盘能力基线"这一设计演化对比。

## 设计类研究 venue（2020–2026）

- **FDG（Foundations of Digital Games）**——设计+分析；近例 *Understanding Disengagement
  From Competitive Multiplayer Games: LoL*（FDG 2025, DOI 10.1145/3723498.3723804）。
- **CHI PLAY**——游戏+HCI、玩家体验与设计。
- **DiGRA / ToDIGRA**——设计理论与分析性游戏研究（agency/counterplay 框架的家）。
- **IEEE ToG / CoG**——游戏设计与分析、玩家建模。
- **AAMAS**——平衡/机制设计形式化（Niantic Bilevel Entropy, AAMAS 2023）。
- **IEEE VIS/TVCG**——当设计论点是分析工具形态时。
